# Profit

A World of Warcraft addon for the **WoW Forever** client (`## Interface: 16001`, a Classic-era
client) that ranks profession crafts by profit using Auctionator prices. README.md covers usage,
the data pipeline and the recording workflow.

## Layout

- `Profit.toc`: load order. `Data/Items.lua`, `Data/Recipes.lua` and `Data/Disenchant.lua` are generated by
  `tools/build_recipes.py`; never edit them by hand.
- `Core.lua`: pricing (`ns.Evaluate`), skill colors, `ns.Rank` (filters and search),
  `ns.BreakdownLines`, `ns.FormatMoney`, and the `/prof` slash commands, including `/prof debug`.
- `Known.lua`: the character's profession skills and known recipes (`ProfitCharDB`), and
  `ns.OpenRecipe`. Supports both modern `C_TradeSkillUI` and Classic trade skill / craft APIs.
- `Record.lua`: records trainer skill levels, merchant items and disenchant results into `ProfitDB`,
  plus the export string. Disenchant results the data didn't predict trigger a popup asking for an export.
- `UI.lua`: the `/prof` window (dropdowns, sortable columns, detail pane; the "Disenchant from AH"
  filter lists items from `ns.DisenchantDeals` instead of recipes) and the copyable text window.
- `Changelog.lua`: release notes (`ns.Changelog`) and the "what's new" popup shown once after
  an update. Add an entry at the top for every release, written for players.
- `Minimap.lua`: minimap button.
- `Tooltip.lua`: disenchant value in item tooltips (`/prof tooltip` toggles it).
- `tools/`: Python scripts that build the data from wago.tools DB2 CSVs and merge recordings
  into `export/recorded.json`. `tools/disenchant.py` holds the disenchant results by hand
  (server loot, not in the client).

## Conventions

- Every file starts `local addonName, ns = ...`; share state through `ns`, not globals.
  Globals (frames, slash commands) are prefixed `Profit`. Never use `Professions...`, which
  collides with Blizzard's `ProfessionsFrame`.
- Code must run on both Classic and modern UI APIs. Check that an API exists before calling it,
  or `pcall` it, and keep a fallback (see `CreateDropdown` in UI.lua and the scanners in Known.lua).
  When adding or changing a game API call, update `API_FEATURES` in Core.lua so `/prof debug`
  reports it.
- Profession names are the English names from the recipe data (`ns.ProfessionNames`).
  Cooking, First Aid and Fishing are secondary (`ns.SecondaryProfessions`).
- Money is in copper. Show it with `ns.FormatMoney`, which uses coin icons.
- Comment style: short comments that explain why or describe the data shape. Keep files compact.

## Checking changes

There's no test suite and no game client here. Syntax-check with `luac -p *.lua`. To test
logic, load `Data/*.lua` and `Core.lua` in plain `lua` with stubbed WoW globals
(`CreateFrame`, `Auctionator`, `ProfitCharDB`, `SlashCmdList`, `strtrim`). Anything in the UI
needs an in-game check, so say what needs checking in game.

## Releases

Pushing a `v*` tag runs `.github/workflows/release.yml`, which packages the addon with the
BigWigs packager (`.pkgmeta`) and uploads it to CurseForge and GitHub Releases. Tags containing
`beta` or `alpha` are uploaded with that release type. `@project-version@` in the .toc is filled
in from the tag. Issues are tracked at github.com/ExcEssIv3/profit.
